# Reporting findings and coverage

Read when writing findings or an acceptance report.

Binary floating point yields a counterexample to almost any ordinary expression, so a failure's value comes from where the software is used. Judge from the affected entry's contract and actual consumers. NumPy, called deep inside software nobody can list, treats a failure on any valid input as real. Where workloads are known, link a failure's input to a problem, contract or workflow from a user report, a project example, guide or release note, a cited paper, or a specific duty in the review profile. Normal representation or unit changes and library intermediates keep that link, and a witness built to test such a problem is fine. A form built only to trigger the mechanism, "a scientist who writes this form", "users bring their own input", a discipline's name, ordinary output, a silent result, a regression or a small fix makes no link. Test at that problem's values and scale. Put a failure without a link in one coverage line as an applicability question, with no severity, repair direction or follow-up. With a link, rarity or extreme values do not remove it.

For each material finding or acceptance claim, give the trigger and affected quantity, current owner/location, independent expected relation, falsifier, relevant legal preservation case, actual result or reusable evidence, concrete repair direction when applicable, and uncovered scope. Scale presentation to the task, using a compact paragraph or table rather than a mandatory new schema. Lead with verified scientific/semantic consequences and material resource defects, then other actionable engineering findings. Report all verified in-scope issues, including pre-existing ones unless excluded. A requested durable report uses a noncolliding path and contains every accepted finding.
Distinguish changed-path inventory, substantive source inspection, traced public workflows and executed validation when reporting coverage. Name material unreviewed surfaces and the scope of sampled checks.
