# API docstrings

Read for comments or docstrings that render a library's public API reference. These rules stand alone and need no review stage beyond the check at the end. For a scientific library's guide pages and rendered reference as a whole, read [library documentation](library-docs.md).

- Follow the project's documentation convention and section order. Give a one-line summary of what the object does or represents, then the information needed to use it. For a callable object, cover its purpose, each parameter's meaning, units and accepted format, return values, and errors and when they occur. For a field or constant, explain its meaning and constraints. Include an example when it clarifies use and link to a guide page when one exists. When the documentation generator cannot show a field's default, write the default into its documentation.
- Write for the caller. Replace words from the code's design, such as owner, ledger or admission, with the reader's words or the object's name, and define a term the reader needs once. Public API names stay as code. Attach a precondition or exception to the parameter, operation, or result it qualifies so the caller can determine when it applies.
- Copy statements of bounds and errors from their source without changing what they bound: relative or absolute, the order, the assumptions, and whether they cover the whole result or one component.
- Comments and docstrings can contain generator directives or flow into generated schemas, command-line help and error output. Identify the outputs the edit reaches and preserve functional directives in a prose-only edit. For Python docstring-only changes, compare syntax trees with docstrings removed. For other languages, use the project's equivalent check of executable content.

Before delivery, check that each changed API comment or docstring gives the information its object requires. Confirm that a caller can identify valid inputs and interpret the result, or understand a field's meaning and constraints. Check that no bound or condition changed its meaning and that functional directives still match the intended behavior.
