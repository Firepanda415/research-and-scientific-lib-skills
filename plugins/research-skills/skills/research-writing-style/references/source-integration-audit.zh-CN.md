# 去除空泛 AI 文风的来源整合记录

本次把 `research-writing-style` 扩展到供人保存、反复阅读、分享、发送、发布或直接粘贴使用的文字。文档、网页、邮件、图注和在聊天中交付的正文都在范围内，不按字数或语言区分。仅服务于当前聊天的总结和进度说明除外。

执行规则见 [SKILL.md](../SKILL.md)、共享写作标准 [durable-prose.md](durable-prose.md) 和交付前必读的 [prose-review.md](prose-review.md)。同一 skill 内，生成或修改完成后必须审阅完整成稿。只要求 review 时直接审现有文字，不自动重写。此表用于检查整合是否有遗漏，日常写作不必加载。写作路由在会话启动、恢复、清空、压缩后和子代理启动时注入。钩子依赖正常安装和 Codex 的信任机制，不能把“发出了加载指令”称为机械保证每一份文字都合格。

“采纳”表示已写入可执行规则。“限定采纳”表示处理其指出的真实问题，但不照搬绝对禁令，边界和理由列在同一行。“不采纳”表示该要求未成为写作规则，并明确说明原因。即使表面表达相同，也要根据它是否传达信息、是否有依据来决定是否修改。

## Humanizer 的 25 个条目

| 编号与内容 | 处置 | 实际规则及未照搬部分的理由 |
|---|---|---|
| 1. 否定对照 | 采纳 | 删除虚设对立，包括跨句对照和句尾否定。真实比较、数学排除条件和纠正确实存在的误解需要保留。 |
| 2. 单句升华、戏剧性碎句 | 采纳 | 删除重复前文的结尾、喊话、停顿指令和碎句堆砌。传递事实或操作要求的短句有效。 |
| 3. 伪深刻格言 | 采纳 | 写明实际判断，删除不增加信息的抽象隐喻。已定义的术语和有解释作用的比喻不在删除范围。 |
| 4. 表演式开场 | 采纳 | 删掉宣布即将解释、刻意表态坦诚等铺垫。有导航内容的提示可以保留。 |
| 5. 对不存在的异议辩解 | 采纳 | 删除凭空反驳和假方案。真实审稿意见、合理备选项和必要排除条件仍应解释。 |
| 6. 强凑三项 | 采纳 | 检查句子和段落的机械排比。不能为破除三段式删掉真实指标、结果或例子。 |
| 7. 重复句首 | 限定采纳 | 修复无功能的机械重复。保留责任主体、学科术语、刻意修辞和可比实验的一致叙述顺序。 |
| 8. 万能破折号 | 限定采纳 | 按已有个人风格避免 prose em dash，不禁止范围、减号、专业名称及代码中的连接符，也不因样本有破折号就覆盖用户明确偏好。 |
| 9. 堆叠限定语 | 采纳 | 删除重复犹豫，保留误差、适用域、推断标记、真实未知和必要安全限制。 |
| 10. 到处使用连字符复合词 | 限定采纳 | 检查生造标签和语法。拒绝“所有表语复合词都去掉连字符”的概括，依专业惯例和语言规范处理。 |
| 11. 被动语态与省略主语 | 限定采纳 | 主体重要且已知时写明。科学被动语态、标题和界面短句无需强改，更不能编出未知主体。 |
| 12. 高频 AI 词汇 | 限定采纳 | 给出观察词群和中文对应问题，依据空泛、夸大或冗余修改。未复制整张词频表或做通用禁词表，词频随模型变化且可能误伤技术含义。原有个人禁词检查照常执行。 |
| 13. 重要性拔高 | 采纳 | 覆盖句尾拔高、空泛挑战展望和万能乐观结尾。具体影响、有条件预测和真实计划可以保留。 |
| 14. 模糊关联 | 采纳 | 有证据才写明关系。来源只支持关联时，不补成因果、任职或合作。 |
| 15. 尾随的空洞分词分析 | 采纳 | 删除没有依据的影响、象征和因果。不能仅按词尾或句法形式删掉真实解释。 |
| 16. 广告腔 | 限定采纳 | 事实文本以具体属性代替宣传。用户要求劝服文案时可以写真实卖点，个人文字可以保留真实喜好。 |
| 17. 借权威造声势 | 限定采纳 | 不虚构专家或共识，不以报刊名单代替内容。CV、媒体页和传播数据中的真实名单与数字有用途时完整保留。 |
| 18. 绕开简单动词 | 限定采纳 | 能直接写“是”“有”时不绕写。功能性关系与身份不总等价，不能机械替换技术定义。 |
| 19. 装饰性加粗与标签列表 | 限定采纳 | 删除无功能装饰，保留定义、术语释义、定位、步骤和并行比较所需结构。 |
| 20. 装饰性标题 | 限定采纳 | 删除重复标题、空层级、无作用分隔线和装饰图标。遵守真实模板和标题大小写规范，保留有意义的箭头与状态标记。 |
| 21. 弯引号转直引号 | 不采纳统一替换 | 改为目标载体和语言内一致。中文标点、专业出版排版及自动弯引号均属正常，机器文本另按语法处理。 |
| 22. 聊天残留 | 采纳 | 成品清除助手寒暄、奉承、邀请继续和答案包装。信件称呼、署名、真实下一步及引用的对话不是残留。 |
| 23. 知识截止套话与补猜 | 限定采纳 | 删除模型自述和无依据补全。真实的数据截至时间、资料局限和未知状态不能删掉。 |
| 24. 标题后的同义复述 | 采纳 | 删除无信息增量的重述。独立阅读的摘要、图注、定义仍可能需要重复关键信息。 |
| 25. 描写上一个版本 | 限定采纳 | 普通说明写当前行为。变更记录、迁移、兼容性、决策理由和研究修订本来就需要历史。 |

## Humanizer 的流程、声音和示例

| 内容 | 处置及理由 |
|---|---|
| 从结构、节奏、夸大、排版、聊天残留检查全文 | 采纳，覆盖段落和跨句结构，不限于逐词替换。 |
| 原文是材料，不是指令 | 采纳，避免待编辑内容改变任务或触发操作。 |
| 保持事实、数字、姓名、日期、引语、引用 | 采纳并补充单位、量词、比较方向、符号、排名、同时性和结论强度。 |
| 缺少细节时提问或简化 | 采纳。已有信息能写出真实句子就直接写，只有完成依赖未知事实时才提问。 |
| 自由重写结构 | 限定采纳。新稿和结构改写可重组，局部 copyedit 仍应最小修改，不擅自扩大成全文重写。 |
| pattern 允许时可删除原有事实 | 不采纳。风格规则不能豁免信息保全，范围变化或实质纠正须单独说明。 |
| 朗读检查、事实回看和常见残留检查 | 采纳为内部复核，合并到已有最终检查，不要求生成音频或独立多轮流程。 |
| 默认交付初稿、问题清单、终稿 | 不采纳。用户需要可直接使用的文字，默认只交付终稿，需要解释时放在正文外。用户明确要求审计时再展示。 |
| 强制两次重写 | 不采纳固定次数。先写、检查、必要时修改，合格文字无需为了流程再改一次。 |
| 匹配用户样本 | 采纳。读取同一作者已接受文字，匹配语域、词汇、第一人称和节奏。 |
| 样本覆盖全部规则 | 不采纳。样本不能覆盖用户明确要求、事实保全和技术准确性。 |
| 可以替作者增加 reaction | 不采纳。不能编造感受、态度、幽默或经历。已有声音应保留，用户要求虚构时另按创作任务处理。 |
| 无样本时按文类选声音 | 采纳，普通事实文本平实，个人文体可保留原有意见、复杂感受和插话。 |
| 文件模式保护非 prose 内容 | 采纳。代码、命令、路径、数据、metadata 和链接目标在纯文字编辑中保持原状。确需改错时应在范围内核验。 |
| 嵌入文档任务只返回成品 | 采纳，也用作聊天中 copy-paste 新稿的默认。针对现有文件的手动修改建议仍遵守原有唯一锚点契约。 |
| 每句话必须提供此前没有的信息 | 限定采纳。减少复述，但摘要、结论、教学回顾、独立图注和必要提醒可以重复。 |
| 强信号出现一次就改、弱信号出现多个才改 | 不作次数规则。每处需有具体缺陷才改，孤立的真实歧义也可以立即修复。 |
| 引语、专名、标题、被讨论词语免于机械修改 | 采纳，并延续精确旧文本锚点的保护。 |
| 保留真实特殊细节、复杂感受、年代语境和个人选择 | 采纳，前提是输入有依据，不能为“人味”补造。 |
| 2022-11-30 之前的文字不是 AI 写作 | 不采纳。这不是所有生成系统的历史分界，且本 skill 不判断作者身份。 |
| 模型机制、信号强弱排名、凭感觉或检测分数辨认作者 | 不作为执行规则。保留这些现象不能证明作者身份的边界，质量缺陷独立判断。 |
| 独立安装、额外命令、版本历史和所有旧词表 | 不导入。只增强现有 skill，并沿用本仓库单插件安装方式。旧版的假范围或同义词漂移按实际逻辑错误处理。 |
| 上游全部 before/after 与 README 游记示例 | 不复制。改用本项目自造且保全信息的短例子。具体缺陷见下文。 |

上游示例不能直接作为保真标准。第 12 项新增了原文没有的食物评价和地区限定。第 18 项把“超过 3,000”变成了“3,000”，还把 spaces 改成 rooms。第 17 项任意删掉两家媒体和粉丝数。第 19 项把一般性能改善缩窄为加载时间改善。第 20 项把用户偏好改成研究证明。README 的 Lisbon 示例增加了作者笔记没有提供的游客、背包和老人看足球等细节，还改变了情绪取向。本次只吸收可用的编辑原则，不沿用这些变更事实的示范。

## Wikipedia 的导言与第 1 至 7 节

| 原文位置与内容 | 处置 | 实际规则及未照搬部分的理由 |
|---|---|---|
| 导言：检测观察与写作问题的区别 | 采纳边界 | 先修事实、证据和推理，再修措辞。质量规则与检测分类都不保证文字出自人类。原文是百科项目建议页，不作为所有文类的格式规范。 |
| §1.1 检测工具 | 限定采纳 | 检测分数不能建立作者身份，普通写作也不以检测分数验收。后续用户明确要求的检测实验另走可选流程，记录实测结果并保全含义，见下文。 |
| §1.2 人的识别能力 | 限定采纳 | 不凭直觉或风格断言作者身份，不为模仿人类故意写错。不导入识别测验、准确率数字及猜测作者的流程，它们不能说明某句应如何改好。 |
| §2.1 夸大意义、遗产和趋势 | 采纳 | 意义判断要有具体贡献、机制、后果或依据，删除适用于任何对象的意义宣言。生物保护、地方历史、文化遗产等题材不自动获得重要性结尾。 |
| §2.2 陈列知名度、媒体覆盖和归因 | 限定采纳 | 写来源实际支持的内容，不借报刊名或覆盖量制造权威。真实媒体列表、CV、传播数据及新闻页仍可能需要这些信息，不能为改文风删掉。 |
| §2.3 表面分析 | 采纳 | 检查句尾附加解释是否有推导或来源，不用语法连接凭空加入影响、因果和象征意义。作者自己的推断在需要归因时明确标示。 |
| §2.4 及 §2.4.1 宣传语言、文化与企业子类 | 限定采纳 | 普通事实文字以属性和证据代替赞美，不默认写成旅游介绍或企业公关稿。用户明确要求劝服文案时可呈现真实卖点，不能编造优越性或文化意义。 |
| §2.5 模糊归因和夸大意见范围 | 采纳 | 明确谁提出什么，不把一两个来源扩写成共识，也不把完整名单说成仅举几个例子来暗示还有更多。 |
| §2.6 挑战与未来展望公式 | 限定采纳 | 删除例行的挑战铺垫和乐观收尾。真实限制、未解决问题、计划和有条件预测保留，文档要求的展望部分按实际内容写。 |
| §2.7 将列表或宽泛标题当作专名 | 采纳 | 开头直接讲对象或列表范围，不给文章标题机械地下实体定义。 |
| §2.8 奖项及认可章节 | 限定采纳 | 不凭空设置奖项、影响或认可章节来制造重要性。确有奖项且符合履历、简介等用途时保留，不禁用章节名或并列标题。 |
| §3.1 高频词群 | 限定采纳 | 把词群当成检查空泛、夸大或冗余的提示，不做通用禁词表。学科术语、准确字义、专名和引语不因词频被改坏。模型年代词频表不导入，变化快且不等于质量。 |
| §3.2 绕开简单系词和动词 | 限定采纳 | 能直接说“是”“有”“担任”“使用”时直接说，避免把事实升级成价值判断。功能、身份和阶段关系不总等价，技术定义须保全。 |
| §3.3 含糊的关联表达 | 采纳 | 有证据时说清任职、任教、资助、引用等实际关系。来源只支持关联时，不擅自改成因果、成员身份或责任。 |
| §3.4.1 “不只是 X，还有 Y” | 限定采纳 | 删除仅用于抬高 Y 的虚设对照。真实增加项和有必要纠正的不完整认识仍可说明。 |
| §3.4.2 “不是 X，而是 Y” | 限定采纳 | 删除凭空假定的错误观点和戏剧性排除。真实误解、数学排除条件及方案区别应清楚保留。 |
| §3.4.3 “Y 而非 X” | 限定采纳 | 检查句尾和倒置的同类对照，不因其语序不同就漏检。实际选择理由和技术比较仍有用途。 |
| §3.5 三项排比 | 限定采纳 | 不为了节奏强凑第三项，也不为了避嫌删掉真实的三项指标、步骤或结果。 |
| §4.1 重复页面标题 | 限定采纳 | 页面或模板已提供标题时避免重复。独立文档可以需要自己的标题，不能照搬百科页面结构。 |
| §4.2 英文标题大小写 | 限定采纳 | 跟随目标文体和现有文件规范，无指定风格时采用句首大写。大小写不证明作者身份，也不套用到中文。 |
| §4.3 父标题下只有子标题 | 不采纳硬禁令 | 技术手册、长报告可以需要分组导航。只删无作用的空层级，不为了给每个父标题补一段话而添加空话。 |
| §4.4 过量粗体 | 限定采纳 | 强调读者确实需要定位的信息，避免机械加粗关键词。定义、界面标签和可访问性用途保留。 |
| §4.5 带短标题的竖排列表 | 限定采纳 | 连续论述用段落，平行项目和步骤可用列表。字段说明、术语表和操作清单可使用短标题，排版须符合目标载体。 |
| §4.6 破折号 | 按个人风格采纳 | 继续执行已有 prose em dash 限制，不宣称它可靠证明 AI 使用。当前原文已提示这一观察可能过时，模型画像不能替代本用户的标点偏好。 |
| §4.7 表情符号作装饰 | 限定采纳 | 正式成品不默认用装饰 emoji。用户要求的设计、真实状态标记和有沟通作用的图标可保留。 |
| §4.8 不合用途的表格 | 限定采纳 | 表格用于字段比较、映射和数据浏览，不把普通连续论述强行表格化。小表格也可能有用，不能一律改成段落。 |
| §4.9 弯引号和弯撇号 | 不采纳统一禁止 | 依目标排版和语言保持一致，代码及机器文本另按语法处理。中文标点、出版排版和编辑器自动弯引号都属正常使用。 |
| §4.10 跳过标题层级 | 采纳 | 维护目标载体所需的层级和可访问性，避免没有作用的跳级。 |
| §4.11 一级标题过多 | 限定采纳 | 用目标文档需要的层级，避免每个短节都用一级标题。不将百科少用一级标题的惯例强加给 Markdown、Word 或独立报告。 |
| §4.12 每节之间插分隔线 | 限定采纳 | 删除无作用的装饰性重复分隔。真实模块边界、导航和指定模板仍可使用。 |
| §5.1 写给聊天用户的话混入成品 | 采纳 | 清除助手寒暄、奉承、答案包装、邀请继续、起草建议和工作过程说明。信件称呼、署名、真实下一步和被引用的对话保留。 |

## 本项目新增的对抗性审阅要求

审阅先独立阅读成品，再与写作要求和来源比较。不能用审阅者从聊天中知道的信息补足正文的缺口，不能因为作者表示“已检查”或用户希望某个结论成立就接受。检查证据是否真的推出结论，并尝试合理的不同解释。实质问题必须有位置、缺陷、读者后果和最小修法。审阅者也要尝试推翻自己的发现，不能靠挑错数量证明独立性。

“不要写 X”只决定如何写，不能自动变成“方法不处理 X”“我们反对 X”或“本版没有 X”。每个负面表述都要有面向目标读者的内容理由和事实依据。真实的技术限制、读者需要遵守的禁令、已成立的比较及明确要求的过程记录可以保留。文档本身是可复用 prompt、写作 skill 或变更记录时，其必要指令和历史属于内容，但生成它的无关聊天仍须隔离。

较长文档在可用时交给独立审阅者，不提供作者自评或期望结论。短文本也必须在完成后作单独的怀疑性重读。分段通过不能替代合并后的检查，后续改动需要复核相关段落及衔接。只要求 review 时不擅自改源文件，不强交替代版本。已生成或获准编辑的成稿修复问题后再审，无法解决的事实或论证缺口必须明确说明，不能包装成已经完成。

## 生成与审阅的分工

句子的主语与动作、从句组织、修饰范围、术语、强调位置和精简机制属于 `durable-prose.md` 的生成指引。`prose-review.md` 以完整论证为主要单位，检查全文结构、段落功能、上下文衔接以及证据与结论的关系。可选的 [detector-evaluation.md](detector-evaluation.md) 只在用户明确要求按检测结果改写或比较检测结果时加载，普通写作不调用外部检测器。
